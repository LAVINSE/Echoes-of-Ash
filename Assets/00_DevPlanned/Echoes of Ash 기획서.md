## 0. 수치 정책 (전역 원칙)

> **본 문서의 모든 수치(SAN 구간·변동량, 드로우/손패 수, AP, 가격, 확률, 예시 카드/유물 효과 등)는 잠정치이며 밸런스 영역이다.** 언제든지 변경될 수 있고, 전부 데이터(ScriptableObject)로 외부화해 코드 수정 없이 조정한다. 문서의 수치는 설계 의도를 전달하기 위한 기준 예시로만 취급한다.
>
> 카드·유물의 구체 효과 예시 역시 전부 **임시 설정**이다. 시스템 구조(효과 분기, 트리거 종류 등)만 확정 사항이고, 개별 수치·효과는 콘텐츠/밸런싱 단계에서 확정한다.

## 1. 게임 개요

| 항목 | 내용 |
|------|------|
| 장르 | 2D 턴제 덱빌딩 로그라이크 |
| 플랫폼 | PC (Steam) |
| 엔진 | Unity 2D (URP) |
| 개발 규모 | 1인 개발 |
| 목표 출시 | Steam 얼리 엑세스 → 정식 출시 |
| 참고 게임 | Slay the Spire (전투/덱빌딩/맵) · Hades (거점 누적 성장) · Dead Cells (드랍·회수 파밍) · Chaos Zero Nightmare (파티 공유 덱) |

### 1-1. 핵심 한 줄 설명
> 1~3인 파티를 꾸려, Slay the Spire처럼 빠르게 덱을 쌓고, Hades처럼 거점을 키우며, Dead Cells처럼 살아 돌아와 파밍하는 2D 턴제 로그라이크

### 1-2. 차별점 3줄 요약
> ① **정신력 시스템** — HP 외에 파티 공유 정신력 게이지(평정/광기 2단계)가 존재. 광기는 고위험 고보상: 반응형 카드가 강화되는 대신 정신력 이벤트(결의 판정 — 던전당 1회 확정 발동)가 리스크로 작동한다. 정신력은 모든 전투원의 필수 스탯이다 — 파티는 공유 게이지 1개, 모든 적은 개별 SAN을 가져 공략 대상이 된다.
> ② **파티 + 공유 덱** — 1~3인 파티(1인 군단 가능). 공용 카드로 덱의 뼈대를 짜고, 영입한 캐릭터의 전용 카드가 부가 시너지로 섞인다. 캐릭터별 순차 턴이 아닌 STS식 공유 턴이라 템포가 가볍다.
> ③ **거점 성장 + 회수 파밍 + 카드 해금** — 죽어도 자원이 남아 거점(집)과 캐릭터 풀을 키운다. 카드 풀은 발견형 자동 해금과 설계도 제작 해금으로 점진 확장되며, 고급 드랍은 살아서 회수하거나 **보관 노드**에서 미리 안전 전송해야 거점에 반영된다.

### 1-3. 설계 철학
- **전투는 검증된 STS 틀로 안전하게** 두고, 게임만의 색은 "전투 바깥"(정신력 운용 · 거점 누적 성장 · 회수 파밍 · 카드 해금)에서 만든다.
- 파티는 CZN 방식을 차용 — 캐릭터별 순차 턴이 아니라 **공유 덱 + 공유 턴**이라 STS의 빠른 템포를 해치지 않는다.
- STS의 단방향 점수 구조가 가진 성장 부족을, **죽어도 쌓이는 거점 성장**으로 메운다.
- **밸런스 기준은 3인 파티.** 1~2인 플레이는 별도 보정 없는 자발적 도전 플레이로 규정한다.

## 2. 핵심 게임플레이 구조

### 2-1. 전체 루프

```
[거점] 파티 편성(1~3인) + 시작 덱 확인 + 시설 점검
    ↓
런 시작
    ↓
맵 탐험 (노드 이동) ←──────────┐
    ↓                          │
전투 / 이벤트 / 상점 / 보관      │ (카드 획득·해금, 드랍 획득: 설계도·시설 재료·자원)
    ↓                          │
카드 획득 + 덱 강화 + 정신력 관리 ─┘
    ↓
다음 층 → 보스
    ↓
런 종료
 ├─ 생존 귀환 (보스 클리어) → 모든 드랍 거점 반영
 └─ 사망 → 기본 자원 + 보관 노드로 전송해둔 아이템만 회수, 나머지 고급 드랍 손실
    ↓
[거점] 자원으로 시설 성장 + 신규 카드/유물/캐릭터 해금
    ↓
(다시 파티 편성 — 더 강한 출발점으로)
```

- 루프는 "등반 후 점수"의 단방향이 아니라 **"거점 ↔ 런"의 순환**이다. 죽음이 끝이 아니라 거점 성장의 재료가 된다.
- 런 도중의 덱 성장은 STS와 동일: **전투/이벤트/상점에서 카드를 획득·선택해 덱에 추가**하며 던전을 진행한다. 등장하는 카드는 **해금된 카드 풀**을 기반으로 한다 (→ 5-3 카드 해금 체계).
- 런의 출구는 **보스 클리어 or 사망** 두 가지뿐이다. 중간 탈출은 없으며, 대신 **보관 노드**(→ 7-3)가 리스크 헤지 수단으로 기능한다.

### 2-2. 전투 구조 (STS 기반 + 파티 공유 덱)

**화면 구성**
```
상단: 적(1~N체) + 각 적의 의도(다음 행동 미리 표시)
중앙: 파티(1~3인) ↔ 적 무리 (정면 대치, 위치 개념 없음)
하단: 공유 손패 카드 | AP 게이지 | 파티 공유 정신력(SAN) 게이지 | 덱/버림 카운터
```

- Slay the Spire 표준 전투를 그대로 채택. 파티와 적은 정면 대치하며 **위치/거리 개념은 없다.**
- **다수 적 조우 있음**: 전투는 적 1~N체와의 조우(Encounter)로 구성된다. 조우 조합은 챕터별 조우 테이블로 데이터 관리한다 (→ 9-3).
- **파티 공유 덱**: 1~3인 파티가 하나의 덱을 공유한다. 손패도 공유. 캐릭터별 개별 덱·개별 턴이 아니다.
- **공유 턴**: 캐릭터마다 순차로 턴을 돌리지 않는다. STS와 동일하게, 한 턴에 공유 손패에서 AP 한도 내로 카드를 낸다. 카드가 누구 소속이든 같은 턴에 사용 가능 → **STS의 빠른 템포 보존** (CZN 방식 차용)
- 카드를 내고, 적 의도를 보고 역산하며, 턴을 종료하면 적이 행동한다.
- 파티원은 각자 **고유 패시브**와 **소수의 전용 카드**로 개성을 낸다 (→ 4장). 전용 카드는 덱의 주축이 아니라 부가 시너지.

**타겟팅 (양방향)**

| 주체 | 방식 |
|------|------|
| 플레이어 → 적 | **STS식 카드 드래그 타겟팅.** 단일 대상 카드는 드래그로 적을 지정, 전체/무작위 대상 카드는 지정 없이 사용 |
| 적 → 파티 | 적별 **대상 선정 규칙**을 데이터로 보유: **랜덤 / 어그로 / 지정(고정)** 중 택. 플레이어는 **도발·지정 계열 카드**로 적의 공격 대상을 개입·조작할 수 있다 |

- 어그로 산정 방식(피해 기여 기반 등)과 도발 카드의 지속 턴 수 등 세부 규칙은 밸런스 영역 (TBD)
- 적 데이터의 대상 선정 규칙 필드는 → 9-1 참조

**HP / 정신력 처리 (파티 단위)**
- **정신력(SAN)은 파티 공유 게이지 1개** (CZN의 팀 스트레스와 동일 계열)
- HP는 **캐릭터별 개별 보유.** SAN 감소는 적의 공격 능력·카드·이벤트 등 다양한 트리거로 발생하며, 특정 한 캐릭터만 피격당해도 파티 공유 SAN이 깎일 수 있다 (피격 판정은 피격자 개인 기준)
- **파티원 전투불능 시**: 해당 캐릭터의 **전용 카드는 드로우 풀에서 제외**된다 — 부활할 때까지 죽은 패로도 손에 잡히지 않음 (공용 카드는 계속 사용). 전멸 시 패배. 부활 수단(휴식 노드/카드/이벤트 등)은 콘텐츠 단계에서 확정

### 2-3. AP (행동 포인트) 시스템
- 매 턴 AP 지급 (파티 공유 풀, 잠정 3점)
- 카드마다 AP 소모량 다름 (잠정 0~3)
- 남은 AP는 다음 턴으로 이월 가능 (잠정 상한 2점)
- AP 이월이 전략적 판단의 핵심

### 2-4. 적 의도 시스템 (STS 방식)
- 적의 다음 행동을 턴 시작 전에 미리 공개 (다수 적일 경우 각 적마다 개별 표시)
- 공격/방어/버프/SAN 압박/특수 행동 아이콘으로 표시
- 플레이어는 이를 보고 카드 선택을 역산

### 2-5. 전투 기본 수치 (Base Data) 정책
> 턴당 드로우 수, 최대 손패, 시작 덱 장수, AP 기본치·이월 상한 등 **전투의 기본 수치는 아직 확정하지 않는다.** 전부 밸런스 영역으로, Balance 데이터로 외부화해 프로토타입에서 조정하며 확정한다. 문서에는 잠정 기준값만 표기한다.

## 3. 정신력(Sanity) 시스템 — 전투의 두 번째 결정축

> ⚠️ 본 장의 모든 수치는 잠정치 (→ 0장 수치 정책)

### 3-1. 파티 정신력 (플레이어 측)

**개념**
- HP와 별개로 **파티 공유 정신력 게이지(SAN)**를 보유
- HP가 "얼마나 버티는가"라면, SAN은 "어떻게 싸우는가"를 결정
- **2단계 구간**으로 단순화 — 평정(Calm) / 광기(Madness)
- 일부 카드는 현재 구간에 따라 **효과가 분기**된다 (모든 카드가 아니라 "정신력 반응형" 카드만)
- 파티 공유이므로, 정신력 운용은 개인이 아니라 **파티 전체의 공동 자원 관리**가 된다

**구간 정의 (잠정치)**

| 구간 | SAN 범위 | 성격 |
|------|----------|------|
| 평정 (Calm) | 40~100 | 안정적. 카드는 표준 효과. 방어·유틸리티에 유리 |
| 광기 (Madness) | 0~39 | **고위험 고보상.** 정신력 반응형 카드가 강화되는 대신, 결의 판정(정신력 이벤트) 리스크가 활성화됨 |

> 임계값은 단일 경계(잠정 SAN 40)로 두어, "경계를 넘나드는 운용" 자체가 전략이 되게 한다.

**광기 구간의 이중 구조 (확정 구조 / 수치 잠정)**

광기는 두 가지 효과가 동시에 작동하는 도박 구간이다:

| 요소 | 성격 | 내용 |
|------|------|------|
| 반응형 카드 강화 | **확정 이득** | 정신력 반응형 카드가 광기 효과로 전환 (고화력·고효율) |
| **정신력 이벤트 (결의 판정)** | **리스크** | **던전당 1회**, 광기 구간에서 맞는 첫 턴 시작에 **확정 발동** (다키스트 던전 결의 판정 방식). **높은 확률로 부정(붕괴), 낮은 확률로 긍정(기인)** |

- **발동 규칙 (개정 — DD 결의 판정 방식):** 파티 공유 SAN이 광기 구간인 상태로 전투의 턴 시작을 맞으면 이벤트 풀에서 무작위 1건이 **확정 발동**한다. 이번 던전에서 이미 발생했으면 다시 발동하지 않는다 (**던전당 1회** — 발생 여부는 런 상태에 기록되고 저장에 편입된다)
- **긍정/부정 분기 = 이벤트별 데이터 소유:** 부정 효과(붕괴)가 기본이며, 긍정 가능 이벤트는 weight 확률로 긍정 효과(기인)를 적용한다. 밸런스 출발점은 DD 기인 확률 대응인 weight 0.25 부근 (잠정)
- 이벤트 예시 (전부 임시): 부정(붕괴) — 손패 1장 무작위 버림 / 자해 피해 / SAN 추가 감소, 긍정(기인) — AP +1 / 드로우 +1 / 다음 카드 피해 증폭
- **잠정 규칙 3종:** ① 턴 중 광기 진입 후 같은 턴 내 회복(순간 스침)은 미발동 — 판정은 턴 시작 시점 (의도 시스템·발화 순서 신뢰성 보존, 적 SAN "턴 경계 판정"과 동일 계열) ② 전투 밖 광기 진입(휴식 선택지 등)은 다음 전투 첫 턴 시작에 발동 ③ 다챕터 런 도입 시(챕터 전환) 발생 기록은 **챕터 전환 시점에 리셋 = 챕터당 1회** (런 전체 1회는 후반 광기 리스크 소멸로 기각)
- **SAN 0에 별도의 고정 페널티(패배 등)는 두지 않는다.** 깊은 광기의 압박은 결의 판정 리스크와 광기 운용 자체가 담당한다 — "낮을수록 강해지지만, 임계를 넘는 순간 정신이 시험받는다"

**SAN 변동 요인 (잠정치)**

| 요인 | SAN 변화 |
|------|----------|
| 강한 적 공격 피격 (피해 ≥ **피격 캐릭터** 현재 HP의 20%) | -10 |
| 저주 카드 드로우 | -8 |
| 특정 광기 카드 사용 (자해형) | 가변 (-5 ~ -15) |
| 적 처치 | +6 |
| 특정 평정 카드 사용 (진정형) | +5 ~ +10 |
| 휴식 노드 진정 | +30 |
| 시설/유물 효과 | ± 가변 |

> 피격 SAN 감소는 **피격당한 캐릭터 개인의 HP 기준**으로 판정한다. 한 캐릭터만 크게 맞아도 파티 공유 SAN이 흔들린다 — "약한 파티원을 노출시키는 것" 자체가 정신력 리스크가 되는 설계.

**정신력 반응형 카드 예시 (임시)**

| 카드 | 평정 효과 | 광기 효과 |
|------|-----------|-----------|
| 어둠의 일격 | 6 피해 | **14 피해 + 자해 3** |
| 떨리는 방패 | 방어막 +10 | 방어막 +4, **드로우 +1** |
| 광란 | 4 피해 ×2 | **4 피해 ×4, SAN -5** |
| 진정의 숨결 | SAN +8 | SAN +15, 이번 턴 공격 불가 |

**설계 의도**
- 정신력은 단순 패널티 바가 아니라 **"낮은 SAN을 의도적으로 활용하는 빌드"**가 성립하도록 양날의 검으로 설계 — 광기 빌드는 결의 판정 리스크를 감수하고 화력을 사는 도박
- 단일 경계를 일부러 출렁이게 만드는 운용 — 광기로 떨어뜨려 한 방 → 다시 평정으로 회복 — 이 **"정신력 댄스"**가 2단계 시스템의 깊이를 만든다 (위처의 스탠스 전환과 유사)
- 광기 친화 캐릭터(예: 흑마술사 계열)는 광기 상태를 적극 유도하는 전용 카드 셋과 직결. 정신력 이벤트의 부정 효과(붕괴)를 완화/역이용하는 카드·유물이 광기 빌드의 핵심 부품이 됨
- 모든 카드를 반응형으로 만들지 않는다. 반응형은 전체 카드의 약 30~40%만. 나머지는 일반 카드로 학습 곡선을 완만하게 유지
- 연출은 화면 채도/비네팅 변화로 가볍게 (아트 부담 최소화)

### 3-2. 적 정신력 (몬스터 SAN)

> 정신력(SAN)은 HP와 같은 **모든 전투원의 필수 스탯**이다. 파티는 공유 게이지 1개(→ 3-1), **모든 적은 개별 SAN 게이지**를 보유한다. "SAN 없는 적"은 존재하지 않는다.

**설계 목적**
- 플레이어의 SAN만 일방향으로 깎이는 구조에 **"적의 정신력도 공략 대상"**이라는 대칭축을 추가
- HP 임계값 패턴 전환에 **SAN 임계값 전환**이라는 두 번째 축을 더해 적/보스 설계의 깊이를 확보
- 모든 적이 SAN을 가지므로 **정신 공격 빌드가 모든 전투에서 성립** — 죽은 패 문제가 원천적으로 존재하지 않는다 (기존 하이브리드/폴백 강제 원칙 폐기)

**동작 방식**
- 적 SAN도 파티와 동일하게 **평정(Calm) / 광기(Madness) 2단계**로 단순화 (시스템 재사용 → 개발 부담 최소화)
- **광기 행동 패턴은 선택적 콘텐츠**: 적별로 광기 패턴을 정의하면 SAN 임계값(적별 설정, 잠정 기준 40) 통과 시 전환되고, **비워두면 광기 구간에서도 기본 패턴을 유지**한다 — 적 22종 전부의 광기 반응을 만들 의무는 없음 (콘텐츠 비용 제어). 광기 반응이 필요한 적/보스만 채운다
  - 예: 평정 상태의 적 → 방어 위주 패턴 / 광기로 떨어진 적 → 고피해·저방어 패턴으로 전환 (플레이어 광기 카드와 대칭되는 디자인)
- **전환 판정은 턴 경계에서만 수행** (권장 규칙): 플레이어 턴 중 SAN이 임계값을 오가더라도 이미 공개된 이번 턴 의도는 유지되고, 턴 종료 시점의 SAN 구간으로 다음 행동/패턴이 결정된다 → 의도 시스템의 신뢰성 보존 + 턴 내 진동 방지
- 적 SAN 감소 요인: 플레이어의 **"정신 공격" 계열 카드/유물**, 특정 상태이상(예: 공포), 자기 자신의 특수 행동(자해형 적)
- 적 SAN 회복 요인: 자체 회복 행동, 시간 경과(턴당 소량 회복) 등 — 밸런싱 단계에서 확정

**광기 보상 보장 원칙 (신규 — ⚠️ 임시 제안, 프로토타입 검증 후 확정)**
- 광기 패턴이 없는(= 행동이 변하지 않는) 다수의 적에게도 정신 공격이 가치를 가져야 한다. 이를 위해 **"광기 상태의 적"에 대한 공통 이득을 최소 1개 보장**하는 방향을 검토한다 (예시 — 전부 임시: 광기 상태 적이 받는 피해 +25% / 광기 진입 턴 행동 1회 상실 등)
- 채택 여부·채택안·수치 전부 밸런스 영역 (TBD). 검증하려는 원칙: **적 SAN을 깎는 행위가 어떤 적에게든 HP 공격과 비교 가능한 대안이 되는가**
- 적을 광기로 몰았을 때 이득인지 손해인지는 **적마다 다르게 설계 가능** (유지) — 광기 패턴이 정의된 일부 적(특히 "정신 오염형" 보스)은 광기일 때 오히려 강해져 플레이어에게 "일부러 건드리지 말아야 할 적"이라는 리스크 판단을 요구

**플레이어 상호작용 (카드/유물 방향성 — 예시는 전부 임시)**
- 정신 공격 카드: 적 HP 대신(혹은 함께) 적 SAN을 깎는 효과. 스킬/공격 카드 일부에 적 SAN 피해 값을 부여
- 예시: "공포의 시선" — 피해 없음, 적 SAN -12 (적을 빠르게 광기로 몰아 고위험 패턴을 유도하거나, 역으로 약체화)
- 모든 적이 SAN을 보유하므로 순수 정신 공격 카드도 죽은 패가 되지 않는다 — 하이브리드/폴백은 강제 원칙이 아니라 카드 개성의 선택지로만 남는다

**UI 원칙**
- 모든 적이 SAN 게이지를 노출하므로 화면 게이지 수가 늘어난다. 파티 측이 공유 게이지 1개인 것으로 총량을 상쇄하고, **적 SAN 게이지는 HP 대비 시각 비중을 축소**(얇은 보조 바)해 STS의 가벼운 템포를 지킨다

**설계 노트**
- AP 이월 + 적 SAN 자연 회복 조합이 "기다렸다 몰아치기" 스톨링을 정답으로 만들지 않는지 프로토타입 우선 검증 항목
- 모든 적 SAN 보유가 매 전투의 인지 부하를 실제로 높이는지 프로토타입에서 확인 — 높다면 "광기 보상 공통 이득"을 단순한 것 하나로 고정해 학습 비용을 낮춘다

## 4. 캐릭터 & 파티 시스템

> 1~3인 파티를 꾸려 런에 나간다. **인원을 다 채울 필요 없으며, 1인 군단도 가능.**

### 4-1. 파티 편성 규칙
- 거점에서 **보유 캐릭터 풀** 중 **1~3인**을 골라 파티를 구성
- 3명을 다 채워도 되고, 1명만으로도 런 진행 가능 ("1인 군단")

**밸런스 기준 (확정)**
- **게임 밸런스는 3인 파티를 기준으로 잡는다.**
- 파티 인원을 줄여서 도전하는 경우 **별도 보정(보너스/핸디캡)은 없다.** 1~2인 플레이는 덱 일관성이라는 자연 이점을 대가로 HP 총량·전용 카드 다양성을 포기하는 **자발적 도전 플레이**로 규정한다.

| 파티 인원 | 덱 성격 | 자연 이점 | 자연 불리 |
|-----------|---------|-----------|-----------|
| 1인 (군단) | 공용 카드 + 1인 전용 카드 → 매우 집중된 덱 | 덱 일관성 최고, 시너지 명확 | HP 풀 적음, 1인 다운 = 즉시 패배, 전용 카드 다양성 부족 |
| 2인 | 공용 + 2인 전용 카드 | 균형 | — |
| 3인 (만석, **밸런스 기준**) | 공용 + 3인 전용 카드 → 시너지 풍부 | 빌드 다양성 최고, HP 총량 많음 | 덱이 넓어져 일관성 관리 필요 |

### 4-2. 캐릭터 구성 요소
- **고유 패시브** — 전투 내내 적용되는 캐릭터별 특성 (예: "광기 구간일 때 이 캐릭터 카드 피해 +20%")
- **전용 카드 세트** — 그 캐릭터를 파티에 넣어야만 덱에 편성 가능한 카드들 (부가 시너지 역할, 수량 TBD)
- **시작 유물** (선택적) — 캐릭터 고유 시작 보너스

### 4-3. 캐릭터 예시 (효과 수치는 임시)

**캐릭터 1 — 유랑 검사** (시작 캐릭터)
- 근성/방어 기반 안정형. 평정 구간에서 강한 정직한 전사
- 패시브: 평정 구간일 때 턴 시작 방어막 +3
- 전용 카드 예: 반격, 재정비, 일섬 등

**캐릭터 2 — 재의 궁수** (2차 개발)
- 다단 히트/지속 피해 기반. 손패 회전이 핵심
- 패시브: 카드 3장 사용할 때마다 드로우 +1
- 전용 카드 예: 연사, 관통, 집중 등

**캐릭터 3 — 흑마술사** (3차 개발)
- HP와 정신력을 동시에 자원으로 쓰는 고위험 고보상
- **광기 구간을 의도적으로 유도**해 폭발적 피해를 노림. 정신력 이벤트의 부정 효과(붕괴)를 완화/역이용하는 전용 카드가 빌드 핵심
- 패시브: 광기 구간일 때 전용 카드 피해 +25%, 단 턴 종료 시 SAN -3
- 전용 카드 예: 어둠의 손, 흡혈, 광란 등

> 캐릭터는 거점 성장으로 **영입/해금**된다 (→ 6장). 초반엔 1명으로 시작해 파밍으로 풀을 늘려간다.

### 4-4. 덱 구조 — 공용 중심 + 전용 부가

| 구분 | 역할 | 비중 |
|------|------|------|
| **공용 카드** | 덱의 뼈대. 누구나 사용. 빌드의 기본 골격 | 덱의 다수 |
| **전용 카드** | 파티에 넣은 캐릭터만 편성 가능. 부가 시너지·색 | 덱의 소수 |

- 덱빌딩의 중심은 어디까지나 **공용 카드**. 전용 카드는 "+α" 양념
- 따라서 카드 물량 부담이 작다 (캐릭터마다 풀 덱 25장을 안 짜도 됨 — 전용은 소수 정예)
- 파티 구성에 따라 어떤 전용 카드가 풀에 열리느냐로 빌드 방향이 갈림
- **파티원 전투불능 시 그 캐릭터의 전용 카드는 부활 시까지 드로우 풀에서 제외** (→ 2-2)

### 4-5. 시작 덱 구성 (데이터 주도)
- **시작 덱에 포함되는 카드 구성은 설계자가 데이터로 정의한다** (파티 편성에 따라 공용 기본 세트 + 편성 캐릭터별 기본 전용 카드가 조합되는 방식)
- 플레이어에게 시작 덱을 어디까지 노출/편집하게 할지(안내 UI, 커스터마이즈 허용 범위)는 **추후 별도 정의**
- **제한 원칙 (로그라이크 묘미 보존):**
  - 시작 덱은 **일반 등급 위주**로 구성
  - 희귀/에픽 카드는 시작 덱에 포함되지 않음 → **런 도중에만 획득 가능**
  - 시작 덱 관련 확장은 거점 성장(수련장)과 연동하되, 구체 방식은 시작 덱 정책 확정 시 함께 정의

## 5. 카드 시스템

### 5-1. 카드 구성 요소

| 필드 | 설명 |
|------|------|
| ID | 고유 식별자 (예: ATK_001) |
| 이름 | 카드 표시 이름 |
| 소속 | 공용(ALL) / 캐릭터 전용(소속 캐릭터 지정) |
| 타입 | 공격/방어/스킬/파워/저주 |
| 카테고리(태그) | 시너지 키워드 태그 (Category SO 참조, 복수 가능 — 예: 화염, 출혈, 도발, 정신공격) |
| AP 비용 | 잠정 0~3 |
| 대상 지정 방식 | 단일(드래그 지정) / 전체 / 무작위 / 자신·아군 |
| 정신력 반응 여부 | 일반 카드 / 정신력 반응형 |
| 평정 효과 | 평정 구간 효과 (효과 블록 리스트) |
| 광기 효과 | 광기 구간 효과 (반응형만, 일반 카드는 동일) |
| 적 SAN 피해 | 적 정신력에 주는 피해량 (해당 카드만, 그 외 0) |
| 등급 | 일반/희귀/에픽 (+ 전설/고유 — 확장 예약) |
| 업그레이드 효과 | 강화 시 변경 내용 |
| 해금 방식 | 발견형(자동) / 제작형(설계도) (→ 5-3) |
| 설명 텍스트 | UI 표시 설명 |

> **등급 체계:** 콘텐츠 목표는 일반/희귀/에픽 3단계 기준으로 잡되, 데이터 구조(enum)에는 **전설(Legend)/고유(Unique)**를 확장 예약분으로 미리 포함한다 (출시 후 DLC·특수 보상용).

### 5-2. 카드 타입별 역할

- **공격 카드** — 적에게 피해. 광기 구간에서 피해가 증폭되는 반응형이 많음
- **방어 카드** — 방어막 획득. 평정 구간에서 안정적, 광기에서는 유틸리티로 전환되는 반응형 존재
- **스킬 카드** — 버프/디버프/상태이상/정신력 조작(아군 SAN·적 SAN)/도발·대상 조작 등 특수 효과
- **파워 카드** — 전투 내내 지속되는 패시브
- **저주 카드** — 적이 덱에 심는 패널티. 드로우 시 SAN 감소. 특정 조건 충족 시 반전 가능 (반전 조건은 콘텐츠 단계 정의 — TBD)

### 5-3. 카드 해금 체계 — 발견형 + 제작형 이원화

> 런 도중 등장하는 카드(전투 보상/상점/이벤트)는 **해금된 카드 풀**에서 추첨된다. 카드 풀은 두 가지 방식으로 영구 확장된다.

| 해금 방식 | 대상 | 동작 | 출처 게임 |
|-----------|------|------|-----------|
| **발견형 (자동 해금)** | 일반 카드 중심 | 미해금 카드가 **낮은 확률로 보상 풀에 섞여 등장**하며, 등장하는 순간 자동으로 영구 해금됨. 그 자리에서 덱에 넣을 수도 있음 | STS식 |
| **제작형 (설계도 해금)** | 희귀/에픽 카드 중심 | 특정 엘리트·보스·이벤트에서 **설계도**를 드랍 → **회수 성공** (생존 귀환 or 보관 노드 전송) → 거점(봉인된 서고)에서 해금. 해금 전에는 보상 풀에 등장하지 않음 | Dead Cells식 |

- 효과: 플레이하기만 해도 카드 풀이 자연스럽게 넓어지고(발견형), 강력한 카드는 "저 보스를 잡아 설계도를 들고 나오자"는 목표 파밍이 된다(제작형)
- 발견형 등장 확률·해금 순서(티어 게이팅 여부)는 밸런스 영역 (TBD)
- 해금된 카드는 이후 모든 런의 전투 보상 / 상점 / 이벤트 풀에 포함된다
- **발견형 해금은 등장 시점에 즉시 영구 확정** — 이후 사망해도 유지

### 5-4. 런 중 카드 획득 경로

| 경로 | 내용 |
|------|------|
| 전투 보상 | 해금 풀에서 3장 제시 중 1택 (or 건너뛰기, STS 표준) |
| 상점 | 골드로 구매 (해금 풀 기반) |
| 이벤트 | 조건부 획득 |
| 발견형 해금 | 미해금 카드가 확률 등장 → 자동 해금 + 즉시 선택 가능 |
| 설계도 드랍 | 카드 자체가 아닌 **설계도**를 획득 → 회수 후 거점에서 해금 (→ 7장) |

### 5-5. 목표 카드 수량

> 덱의 중심은 **공용 카드**. 전용 카드는 부가 시너지라 캐릭터당 소수만 둔다 (개별 풀 덱을 짤 필요 없음 → 물량 부담 감소).

| 구분 | 수량 |
|------|------|
| **공용 카드** | **50장** (덱의 뼈대 — 비중 최대) |
| 캐릭터 전용 카드 | 캐릭터당 소수 (장수 TBD — 부가 역할) |
| 저주 카드 | 10장 |
| **목표 총합** | **약 90~110장** (전용 카드 확정 시 조정) |

이 중 약 30~40%는 **정신력 반응형** 카드로 설계.

> **전용 카드 수량은 콘텐츠 확장 단계에서 확정.** 부가적 역할이라는 성격(소수 정예)만 고정하고, 실제 장수는 캐릭터 수·밸런싱에 맞춰 결정한다.

## 6. 거점(집) 시스템 — 핵심 차별점

> STS는 클리어 시 점수·해금만 남아 성장 요소가 제한적. 거점 시스템이 이 빈자리를 채운다.
> **꾸미기·비주얼 커스터마이징은 없다** (1인 개발 + 아트 비중 최소화). 아이콘 + 텍스트 + 수치로 굴러가는 **메뉴형 시스템 성장.**

### 6-1. 거점의 역할
- 런과 런 사이에 머무는 공간. 모든 메타 성장이 여기서 일어남
- 시설 목록을 업그레이드/해금하고, 파티를 편성하고, 다음 런을 준비
- 죽어도 자원이 남으므로 거점은 **항상 우상향**한다 (좌절감 최소화)

### 6-2. 거점 성장의 이원화 (Hades + Dead Cells)

| 성장 종류 | 방식 | 출처 게임 | 성격 |
|-----------|------|-----------|------|
| **기본 시설 레벨업** | 기본 자원(골드/공용 재료)만 모으면 해금 | Hades식 | 관대. 꾸준히 우상향. 좌절감 적음 |
| **고급 시설 / 희귀 콘텐츠 해금** | 특정 드랍 재료·설계도를 파밍 + 회수해야 해금 | Dead Cells식 | 조건부. 목표 지향 파밍 동기 제공 |

> 두 게임의 장점만 분리 취득: 시설 성장은 끊김 없이 성장하고, 희귀 콘텐츠는 "이 보스를 노려 잡자"는 긴장과 목표를 만든다.

### 6-3. 시설 예시

| 시설 | 효과 | 성장 방식 |
|------|------|-----------|
| 회복소 | 런 시작 HP/SAN 상한·회복량 강화 | 기본 (관대) |
| 수련장 | 카드 업그레이드 해금, 시작 덱 관련 확장(정책 확정 시 정의) | 기본 (관대) |
| 보관고 | 회수 가능 자원량·드랍 슬롯 증가, **보관 노드 전송 가능 개수 확장(연동 제안)** | 기본 (관대) |
| **막사** | **신규 캐릭터 영입/해금 (파티 풀 확장)** | 기본+고급 혼합 |
| 제련소 | 고급 유물 해금 | **고급 (드랍 재료 필요)** |
| 봉인된 서고 | **제작형 카드 해금 (설계도 소모)** | **고급 (설계도 회수 필요)** |
| 광기의 제단 | 정신력 관련 시작 보너스/특수 시작 옵션 | **고급 (보스 드랍 필요)** |

> **막사(캐릭터 영입):** 파티는 1명으로 시작해 막사에서 캐릭터를 늘려간다. 기본 캐릭터는 자원으로 관대하게 영입되고, 일부 강력한 캐릭터는 특정 보스 드랍·설계도를 회수해야 해금되는 조건부(데드셀식)로 둔다. 캐릭터 영입은 파티 시스템이 거점 성장에 부여하는 **새로운 메타 축**이다.

## 7. 드랍 & 회수 시스템 — Dead Cells식 파밍

### 7-1. 드랍 테이블
- 적/이벤트마다 **드랍 테이블**을 가짐
- 드랍 항목은 **3가지 타입**으로 구분:

| 드랍 타입 | 내용 | 회수 리스크 |
|-----------|------|-------------|
| 일반 자원 | 골드, 공용 재료 | **없음** (죽어도 회수) |
| 시설 재료 | 고급 시설 해금용 특수 재료 | **있음** (고급만) |
| 카드 설계도 | 제작형 카드 영구 해금 도면 | **있음** |

- 드랍 테이블은 적별로 차별화: "이 엘리트는 시설 재료 위주, 저 보스는 카드 설계도 위주" → 노리고 잡는 파밍 동기

### 7-2. 회수 규칙 (절충형 — 확정)

> **기본은 회수, 고급만 리스크.** 런의 출구는 보스 클리어 or 사망뿐이며, 중간 탈출은 없다. 대신 **보관 노드**가 리스크 헤지 수단이다.

| 상황 | 일반 자원 | 시설 재료 / 설계도 (고급) |
|------|-----------|---------------------------|
| **생존 귀환** (보스 클리어) | 전량 회수 | 전량 회수 → 거점 영구 반영 |
| **사망** | 전량 회수 (Hades식 관대) | **손실** — 단, **보관 노드로 미리 전송한 것은 보존** |

- 효과: 일반 진행은 죽어도 손해가 적어 "한 판 더"가 가벼움. 그러나 희귀 드랍을 든 순간 **"욕심내서 더 파밍할까 vs 보관 노드에 맡길까 vs 끝까지 들고 갈까"**의 긴장이 발생
- 정신력과 연동: SAN이 바닥나면 런이 위태로워지므로, 고급 드랍을 들고 있을 때 정신력 관리가 곧 회수 판단이 됨

### 7-3. 보관 노드 (신규)

> 맵에 배치되는 노드 타입. **사망 시 소멸되는 고급 아이템(시설 재료·설계도)을 개수 제한 내에서 즉시 거점으로 전송**하는 안전 금고.

**동작 규칙**
- 보관 노드 도착 시, 현재 소지 중인 손실 리스크 아이템 중 **제한 개수만큼 선택해 거점으로 즉시 전송** (잠정 1~2개 — 밸런스 영역)
- 전송된 아이템은 이후 사망해도 **거점에 보존** (런 종료 시 정산에 합산)
- 전송 가능 개수는 **보관고 시설 레벨과 연동해 확장** 가능 (제안 — 거점 성장이 런 중 안전망을 키우는 연결고리)

**설계 의도**
- 중간 탈출 없이도 "보상에 대한 리스크 감수" 선택지를 제공: 전부 맡기면 안전하지만 노드 하나를 소비하고, 들고 가면 전량 회수를 노리는 도박
- 노드 선택 자체가 성장 선택지가 됨 — 보관 노드로 향하는 동선 vs 엘리트/이벤트로 향하는 동선의 트레이드오프 (해당 던전에서의 전투·성장 선택지 제공)
- 맵 배치 비율·챕터별 등장 수는 밸런스 영역 (→ 10-2)

### 7-4. 설계 노트
- 회수 강도가 너무 세면 STS의 가벼운 템포가 죽고, 너무 약하면 회수의 긴장이 사라진다 → 절충형 + 보관 노드가 균형점
- 보관 노드가 너무 흔하면 리스크가 무의미해지고, 너무 귀하면 사실상 없는 것과 같다 → 배치 밀도가 핵심 밸런스 변수

## 8. 유물 시스템

> 유물 예시·효과는 전부 임시 (→ 0장 수치 정책). 구조(트리거 체계, 정신력 연동)만 확정.

### 8-1. 유물 구성 요소

| 필드 | 설명 |
|------|------|
| ID | 고유 식별자 (예: REL_001) |
| 이름 | 유물 표시 이름 |
| 등급 | 일반/희귀/보스 |
| 소속 | 전용 캐릭터 or 공용 |
| 발동 조건 | 패시브 / 전투 시작 / 턴 시작 / 카드 사용 시 / **피격 시(OnTakeDamage)** / **가해 시(OnDealDamage)** / 전투 종료 시(검토) |
| 카테고리(태그) | 참조 태그 (Category SO — 예: "화염 카드 사용 시" 류의 태그 연동 유물용) |
| 효과 설명 | 효과 텍스트 |
| 정신력 연동 여부 | Y/N (특정 SAN 구간에서만 발동하는 유물) |

**트리거 체계 노트**
- **피격/가해 분리 (확정):** 피해 관련 트리거는 "내가 피해를 입을 때(OnTakeDamage)"와 "적에게 피해를 입힐 때(OnDealDamage)"로 구분한다. 발동 주체와 전달 파라미터(공격자/피해량/대상)가 다르므로 통합하지 않는다.
- **전투 종료 트리거 (재검토 권장):** "승리 시" 트리거는 패시브와 다르다 — 패시브는 전투 중 상시, 전투 종료는 **전투가 끝난 시점 1회** 발동(예: "전투 승리 시 HP 3 회복" 류의 STS 표준 아키타입). 전투 후 회복/보상형 유물을 만들 계획이 있다면 `OnBattleEnd`(승/패 구분 파라미터)로 유지 필요. 해당 아키타입을 만들지 않기로 하면 제거 확정.

### 8-2. 정신력 연동 유물 예시 (임시)

| 유물 이름 | 효과 |
|-----------|------|
| 광인의 부적 | 광기 구간일 때 모든 공격 피해 +25% |
| 평정의 추 | 평정 구간일 때 턴 시작 시 방어막 +5 |
| 깨진 거울 | SAN이 평정/광기 경계를 넘을 때마다 카드 1장 드로우 (**턴당 발동 횟수 제한 필요** — 경계 왕복 무한 엔진 방지) |
| 망각의 구슬 | 매 턴 SAN -3. 대신 첫 카드 AP 0 |

### 8-3. 목표 유물 수량

| 구분 | 수량 |
|------|------|
| 일반 유물 | 25개 |
| 희귀 유물 | 15개 |
| 보스 유물 | 6개 |
| 정신력 연동 유물 | 10개 |
| **총합** | **56개** |

## 9. 적 시스템

### 9-1. 적 데이터 구성 요소

> **설계 원칙:** "SAN 압박"은 적의 고정 스탯이 아니라 **행동 패턴의 한 타입**이다. 플레이어 SAN을 깎는 행위는 공격/방어와 같은 층위의 행동(SAN_PRESSURE)으로 행동 패턴 배열 안에 정의하며, 별도 데이터 필드로 두지 않는다. 적의 SAN 최대치·임계값·광기 패턴은 적의 고유 속성이므로 데이터 필드로 정의한다. SAN 보유 여부 필드는 없다 — 모든 전투원이 보유하는 필수 스탯이기 때문 (→ 3-2).

| 필드 | 설명 |
|------|------|
| ID | 고유 식별자 (예: ENE_001) |
| 이름 | 적 이름 |
| 챕터 | 등장 챕터 (1/2/3/보스) |
| 카테고리(태그) | 적 계열 태그 (Category SO — 예: 정신 오염형, 언데드, 야수) |
| HP | 기본 HP |
| **대상 선정 규칙** | **RANDOM(무작위) / AGGRO(어그로 기반) / FIXED(지정 고정)** — 파티 중 누구를 공격할지의 기본 AI. 플레이어의 도발·지정 카드가 이를 덮어쓸 수 있음 |
| 행동 패턴 | 행동 순서 배열 (AI 순환). 각 행동은 타입(공격/방어/버프/**SAN 압박**/특수)과 수치를 가짐 |
| HP 페이즈 전환 | HP 임계값 도달 시 변경되는 행동 패턴 (해당 적만) |
| **적 SAN 최대치** | SAN 최대값 (필수, 잠정 기본 100) |
| **적 SAN 임계값** | 평정/광기 전환 경계 (잠정 기본 40, 적별 조정) |
| **SAN 페이즈 전환** | 광기 진입/이탈 시 변경되는 행동 패턴 (선택 — 비워두면 광기에서도 기본 패턴 유지, 판정은 턴 경계 → 3-2) |
| 드랍 테이블 ID | 이 적이 드랍하는 항목 묶음 (→ 7장) |
| 특수 능력 | 고유 메커닉 설명 |
| 보스 여부 | Y/N |

### 9-2. 행동 패턴 설계 원칙
- 모든 적의 행동은 순환 패턴으로 미리 정해져 공개 (STS식 의도 시스템, 다수 적은 각자 표시)
- 행동 타입: 공격 / 방어 / 버프·디버프 / **SAN 압박 (플레이어 SAN 감소)** / 특수
- 패턴 전환 트리거는 두 가지: **HP 임계값** / **적 SAN 임계값** (정신력 보유 적만, 턴 경계 판정)
- 일부 적은 SAN 압박 행동 위주로 구성: 직접 피해는 약하지만 플레이어를 광기로 밀어넣어 간접 위협

### 9-3. 조우(Encounter) 시스템 (신규)

> 전투는 적 단일이 아니라 **적 1~N체의 조합(조우)** 단위로 발생한다.

| 필드 | 설명 |
|------|------|
| 조우 ID | 고유 식별자 (예: ENC_CH1_03) |
| 챕터 / 노드 타입 | 등장 챕터, 일반/엘리트/보스 구분 |
| 적 구성 | 적 ID 목록 (1~N체, 동일 적 중복 가능) |
| 등장 가중치 | 조우 테이블 내 추첨 가중치 |
| 난이도 계수 | 층수 진행에 따른 등장 구간 제어 (초반/중반/후반) |

- 다수 적 조우에서의 전략: 처치 순서 결정(위협 우선순위), 전체기 vs 단일기 카드 가치, SAN 압박형 적을 먼저 자를지 판단 등 — STS 다수전의 재미를 그대로 가져옴
- 조우당 최대 적 수는 UI/가독성 고려해 잠정 3~4체 상한 (밸런스 영역)

### 9-4. 목표 적 수량

| 구분 | 수량 |
|------|------|
| 챕터 1 일반 적 | 6종 |
| 챕터 2 일반 적 | 6종 |
| 챕터 3 일반 적 | 6종 |
| 중간 보스 | 3종 |
| 최종 보스 | 1종 |
| **총합** | **22종** (조우 조합으로 체감 다양성 확보) |

> 이 중 자체 정신력을 보유하는 적은 소수 (보스 + 일부 엘리트, → 3-2). 조우 테이블 수량은 콘텐츠 단계에서 확정.

## 10. 맵 시스템 (STS 방식)

### 10-1. 맵 구조
- 3개 챕터, 챕터당 6~8층
- 각 층마다 2~3개 분기 노드
- 노드 타입: 전투 / 엘리트 전투 / 이벤트 / 상점 / 휴식 / **보관** / 보스

### 10-2. 노드 비율 (챕터당, 잠정)

| 노드 타입 | 비율 (잠정) | 특징 |
|-----------|------|------|
| 일반 전투 | 40% | 카드/자원 보상 (조우 테이블 기반) |
| 엘리트 전투 | 15% | 유물 + **드랍 테이블** (시설 재료·설계도) |
| 이벤트 | 20% | SAN 거래, 카드 선택, 스토리 |
| 상점 | 10% | 카드/유물 구매, 카드 제거 |
| 휴식 | 10% | HP/SAN 회복 or 카드 업그레이드 |
| **보관** | **5%** | **고급 드랍 개수 제한 거점 전송 (→ 7-3)** |

> 비율은 전부 밸런스 영역. 특히 보관 노드 밀도는 회수 긴장감을 좌우하는 핵심 변수 (→ 7-4).

### 10-3. 맵 생성 규칙
- 시드(Seed) 기반 절차적 생성
- 보스는 항상 최하층 1개 노드로 고정
- 같은 타입이 3층 연속 이어지지 않도록 제한
- 보관 노드는 챕터당 최소 1개 보장 검토 (밸런스 영역)

## 13. 메타 프로그레션 정리 (런 간 성장)

> 거점 시스템(6장)이 메타 성장의 본체. 여기서는 전체 진행 보상을 정리.

- **생존 귀환 추가**: 그 런에서 획득한 모든 고급 드랍(설계도·시설 재료) 회수
- **보관 노드 전송분**: 사망 여부와 무관하게 보존 (→ 7-3)
- **발견형 카드 해금은 즉시 영구 반영** (등장 시점에 해금 확정 — 사망과 무관)

### 13-2. 거점 해금 트리
- 신규 캐릭터 영입 해금 (막사)
- 카드 업그레이드·시작 덱 관련 확장 (수련장)
- 제작형 카드 해금 (봉인된 서고 — 설계도 소모)
- 신규 유물 해금 (제련소)
- 정신력 특수 시작 옵션 (광기의 제단)
- 보관 노드 전송 개수 확장 (보관고 — 제안)
- 난이도 상승 옵션 (Ascension) 해금

## 15. 개발 원칙 & 아키텍처

> 1인 개발에서 유지보수 비용을 최소화하기 위해, 코드 구조는 아래 원칙을 준수한다.

### 15-1. SOLID 원칙 준수

| 원칙 | 적용 방침 |
|------|-----------|
| **S** — 단일 책임 | 카드 효과 처리 / 정신력 관리 / 턴 진행 / 타겟팅 / UI 갱신을 각각 별도 클래스로 분리. 하나의 클래스는 하나의 변경 이유만 가진다 |
| **O** — 개방-폐쇄 | 카드 효과·유물 발동·적 행동은 인터페이스/추상 기반으로 설계해, 신규 콘텐츠 추가 시 기존 코드 수정 없이 확장 |
| **L** — 리스코프 치환 | 파생 효과 클래스는 항상 상위 타입으로 치환 가능하게. 특수 카드도 공통 실행 파이프라인을 깨지 않도록 설계 |
| **I** — 인터페이스 분리 | 거대 인터페이스 금지. 피해 대상(`IDamageable`), 정신력 보유(`ISanityHolder`), 상태이상 대상(`IStatusReceiver`), 타겟 가능(`ITargetable`) 등 역할별 소형 인터페이스로 분리 — **`ISanityHolder`는 `IDamageable`과 같은 모든 전투원의 기본 계약** |
| **D** — 의존성 역전 | 상위 시스템(전투 매니저 등)은 구체 클래스가 아닌 추상에 의존. 데이터(ScriptableObject)와 로직을 분리 |

### 15-2. 모듈식 프로그래밍
- 시스템을 독립 모듈로 분리: **전투 / 정신력 / 덱·카드 / 파티 / 타겟팅 / 조우 / 드랍·회수 / 거점 / 맵 / 이벤트 / 상점 / 메타 저장**
- 모듈 간 직접 참조 최소화 — 이벤트 버스(또는 C# event) 기반 통신으로 결합도 낮춤. **이벤트 구독·발동 순서는 결정적으로 보장** (유물 다중 발동 시 획득 순 고정 등 — 리플레이/버그 재현성 확보)
- 정신력 모듈은 **파티/적 공용**으로 설계 (동일 SAN 로직을 양측이 재사용 → 적 SAN 확장 비용 최소화)
- 데이터는 ScriptableObject로 외부화, 로직은 데이터를 해석만 함 (데이터 주도 설계)
- 각 모듈은 단독 테스트 가능한 단위로 유지 (전투 모듈만 별도 씬에서 구동 가능하게)

### 15-3. 카드 효과 = 효과 블록 조합 구조
- 카드 100여 장을 카드당 클래스로 만들지 않는다. 카드 = **효과 블록의 리스트**(피해 / 방어막 / SAN 증감 / 적 SAN 피해 / 드로우 / 상태이상 / 도발 …)로 데이터에서 조합
- 정신력 반응형 카드는 "평정 효과 블록 리스트 / 광기 효과 블록 리스트"를 별도 보유
- 신규 카드 대부분이 **코드 0줄**로 추가되는 것이 목표. 진짜 특수한 카드만 커스텀 효과 클래스 작성

### 15-4. enum vs Category 사용 기준

| 구분 | 기준 | 해당 |
|------|------|------|
| **enum** | 코드가 switch/분기하는 **닫힌 집합**. 추가 시 코드 수정이 자연스러움. 순서/비교 의미 보유 | 카드 타입, 정신력 구간, 유물 트리거, 아이템 타입, 희귀도 |
| **Category (SO)** | 콘텐츠끼리 참조·필터하는 **열린 태그**. 에셋 추가만으로 확장, 코드 수정 없음 | 시너지 키워드(화염·출혈·정신공격…), 적 계열(정신 오염형·언데드…), 카드 아키타입 태그 |

- 판별 질문: **"이 값이 늘어날 때 코드도 바뀌어야 하는가?"** Yes → enum, No(데이터끼리 참조만) → Category
- Category 활용 예: "화상 카드 사용 시마다 추가 피해 +2" 유물 — 태그가 Category면 유물 데이터가 Category 에셋을 참조하는 것만으로 성립 (코드 0줄)
- **상태이상 (하이브리드 검토):** 종류를 계속 확장할 경우 enum+switch가 비대해짐. 상태이상 정의(수치·아이콘·설명)는 `IdentifiedObject` 파생 SO로, 고유 틱 로직만 상태이상별 클래스 매핑하는 하이브리드 구조 권장. 5~6종 이내 유지 시 enum도 충분
- **유물 트리거 확정 사항:** 피격(OnTakeDamage)/가해(OnDealDamage) 분리 유지. 전투 종료 트리거(OnBattleEnd)는 전투 후 발동형 유물 제작 여부에 따라 재추가 검토 (→ 8-1)

### 15-5. 런타임 인스턴스 / 저장
- 전투 중 카드 인스턴스(강화·일시 버프 상태)는 SO 복제(`Instantiate`)가 아닌 **런타임 래퍼(CardInstance) 클래스**로 관리 — 원본 SO는 불변 데이터, 가변 상태는 래퍼가 보유 (메모리·직렬화 유리)
- 저장 스키마에 **버전 필드 + 마이그레이션 계층**을 처음부터 포함 — 거점 진행도·해금 상태가 영구 누적되는 게임이라 EA 이후 패치마다 세이브 호환이 필요
- 시드 기반 맵과 함께 **결정성(같은 시드 = 같은 런) 보장 여부**를 Phase 2에서 결정 (런 중 저장 방식과 직결)

- [ ] 모든 적이 SAN을 가져도 매 전투의 템포와 가독성이 유지되는가? (게이지 UI 비중, 인지 부하)
- [ ] 정신 공격이 어떤 적 상대로도 HP 공격과 비교 가능한 대안인가? (광기 보상 보장 원칙 — 임시 — 작동 확인)

- [ ] 코드가 SOLID·모듈 원칙을 유지하는가? (신규 카드/유물/적 추가 시 기존 코드를 수정하지 않고 확장되는가)
